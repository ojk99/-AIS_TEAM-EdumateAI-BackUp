# [프로젝트 기획서 초안] EduMate AI
> 다분야 단원 목차 체계 기반 AI 맞춤형 튜터 & 온디맨드 퀴즈 플랫폼

---

## 1. 프로젝트 개요 (Overview)
- **프로젝트명**: EduMate AI (에듀메이트 AI)
- **기획 취지**: 경직된 O/X 채점과 정형화된 문제 풀이에서 벗어나, 표준 단원 목차 흐름에 맞춘 AI 개념 설명·실시간 문제 출제·서술형 문맥 정밀 평가를 제공하는 다분야 학습 플랫폼 구축.
- **주요 목표**:
  1. 폭넓은 학습 영역(기초 코딩, 일본어, 중국어, 국/영/수/사/과 등)의 단원 목차 연동 및 실시간 튜터링 환경 구축.
  2. 사전 문제은행 구축 또는 100% 실시간 온디맨드 출제를 유연하게 채택하여, AI가 4대 유형(OX, 객관식, 주관식, 서술형)의 문제를 즉석 생성.
  3. AI가 문제 복잡도에 따라 난이도(하: 1점 / 중: 3점 / 상: 5점)를 자체 배점하고, 서술형 풀이에 대해 문맥 기반 부분 점수(1\~5점)를 공정하게 부여.
  4. 복잡한 시스템 구축 리스크를 배제하고, 공통 웹/서버 템플릿 위에 각 팀원의 과목별 AI 파이프라인을 플러그인 형태로 결합하는 고효율 협업 구현.

## 2. 핵심 기능 상세 (Core Features)

### ① AI 온디맨드 멀티 유형 문제 생성 & 1·3·5 난이도 배점
- **4대 문제 유형 자유 출제**: 학습자의 선택과 단원 특성에 맞춰 AI가 최적의 유형을 동적 출제.
  - **OX 퀴즈**: 핵심 개념 참/거짓 판별 (기초 점검)
  - **객관식(4지선다)**: 실전 개념 적용 및 문법/어휘 선택
  - **단답형 주관식**: 핵심 키워드, 명령어, 수치 결과 입력
  - **서술형**: 풀이 과정, 코드 작성 이유, 문장 해석 및 논리 기술
- **AI 자체 난이도 판정 및 기본 배점**:
  - **하 (기초)**: 1점 (개념 확인)
  - **중 (발전)**: 3점 (개념 응용)
  - **상 (심화)**: 5점 (복합 문제 및 고난도 서술)

### ② 서술형 AI 문맥 채점 & 1\~5점 세부 부분 점수 시스템
- **정밀 문맥 채점 (Semantic Evaluation)**: 단순 키워드 일치 여부만 보지 않고, 작성된 답안의 핵심 원리 반영도와 논리적 완성도를 AI가 종합 판단.
- **유연한 5단계 부분 점수 부여**:
  - **5점 (만점)**: 핵심 논리와 키워드가 완벽하며 설명이 명확한 경우
  - **3\~4점 (우수)**: 핵심 의도는 맞으나 일부 부가 설명이나 디테일이 부족한 경우
  - **1\~2점 (노력)**: 전체적인 방향은 틀렸으나 일부 유의미한 개념/키워드를 언급한 경우
  - **0점 (오답)**: 전혀 엉뚱한 내용을 서술하거나 백지로 제출한 경우
- **심플 원포인트 피드백**: 감점된 구체적 이유와 올바른 풀이 방향을 초보자 눈높이에 맞춰 1\~2문장으로 명쾌하게 안내.

### ③ 단원 목차 RAG 기반 실시간 개념 튜터링
- **경량 RAG 기반 요약 과외**: 단원 목차 텍스트/DB를 연동하여 학습자가 특정 단원을 선택하거나 질문할 경우, 핵심 개념어 중심의 맞춤형 요약 과외 제공.
- **학습자 피드백 수용**: "이해하기 어려워요", "비슷한 난이도로 더 풀어볼래요" 등의 학습자 요청에 따라 AI가 즉각적으로 설명 톤을 바꾸거나 유사 난이도 문제 재출제.

### ④ 랭킹 및 레벨 시스템
- **경험치 및 성장**: 문제 해결 및 서술형 부분 점수 획득에 따른 누적 점수 기반 레벨업 시스템 운영.

## 3. 심화 / 확장 영역 (Advanced Features - 일정 및 완성도에 따른 선택 구현)

### 💡 심화 1. 단원 진행도 파라미터(Unit Progress Parameter) 추적
- **개념**: 학습자가 각 과목에서 어떤 단원을 어디까지 학습했는지 진행도(예: python_unit_2: 70%)를 수치 데이터로 기록.
- **AI 연동**: AI 출제 엔진에 이 진행도 파라미터를 넘겨주어, 진도가 높은 단원은 심화 문제, 신규 진입 단원은 기초 개념 문제로 난이도를 정밀 조절.
- **UI 표기**: 화면 상단에 단원 진행도 프로그레스 바(Progress Bar) 시각화.

### 💡 심화 2. RAG 기반 개인화 오답노트
- **개념**: 학생이 과거에 틀렸던 문제와 피드백 기록을 Vector DB에 저장해 두었다가, 취약 단원 집중 복습 퀴즈를 자동으로 구성해 주는 기능.

## 4. 추천 기술 스택 (Tech Stack)

## 5. 단계별 개발 로드맵 (Roadmap)

- **Phase 1. 공통 뼈대 구축 & 단원 목차 텍스트 수집 (1주차)**
  * 과목별 단원 목차 txt 수집 및 Pandas를 통한 SQLite DB 적재 (원샷 스크립트 구축)
  * 공통 데이터 입출력 표준 양식(JSON Schema) 확정 및 GitHub 협업 세팅
- **Phase 2. 공통 웹/서버 템플릿 제작 & 과목별 AI 모듈 독립 개발 (2주차)**
  * 메인 FastAPI 서버 기본 뼈대 및 기본 문제 풀이 UI 화면(HTML/CSS) 구축
  * 각 팀원은 본인 담당 과목의 출제/서술형 채점 파이썬 모듈(`[과목]_agent.py`) 개발
- **Phase 3. 모듈 결합 & 엔드투엔드(E2E) 테스트 (3주차)**
  * 메인 서버에 각 조원이 개발한 과목별 모듈을 플러그인 형태로 임포트하여 화면과 연결
  * 4대 유형 정상 출제 및 서술형 1\~5점 부분 점수 채점 정상 동작 테스트
- **Phase 4. 완성도 강화 & 심화 기능 선택 적용 (4주차)**
  * 오답 원포인트 피드백 문구 다듬기, 예외 처리(빈 답안 제출 등 방어 로직) 강화
  * (여유 시) 단원 진행도 파라미터 프로그레스 바 등 심화 기능 추가
- **Phase 5. 최종 배포 & 포트폴리오 문서화 (5주차\~완성)**
  * 클라우드 배포, README.md 기술 문서 정리, 팀원별 담당 과목 기여도 명시

## 6. 팀원 역할 분배 및 협업 전략 (공통 뼈대 + 플러그인 방식)

### ① 공통 인터페이스 및 가이드라인 수립 (프로젝트 리더 주도)
- **JSON Schema 규격 통일**: AI가 문제를 뱉어낼 때 사용할 키 이름(`question_type`, `difficulty`, `base_score`, `question`, `options`, `answer`, `explanation`) 통일.
- **점수 룰 통일**: 기본 난이도(1, 3, 5점) 및 서술형 부분 점수(1\~5점) 채점 기준표 확정.

### ② 과목별 전담제 (제비뽑기 분배)
- **과목 자율 선택/배정**: 기초 코딩(Python), 제2외국어(일본어/중국어), 일반 교과목(국/영/수/사/과) 등 팀원 희망 분야 배정.
- **독립 모듈 개발**: 각 팀원은 `services/` 폴더 아래 본인 과목 파일(`korean.py`, `python.py` 등) 안에서 프롬프트 엔지니어링 및 Gemini API 호출 로직만 전담 개발.

### ③ 중앙 서버 통합 및 기대 효과
- **병풍 없는 확실한 1인 1지분**: "저는 이 프로젝트에서 파이썬 기초 코딩 문제 출제 및 서술형 코드 평가 AI 파이프라인을 전담 개발했습니다"라고 면접에서 100% 당당히 어필 가능.
- **충돌 없는 안전한 병합**: 서로의 코드를 건드릴 일 없이 본인 파일만 작업해 Pull Request를 보내므로 깃허브 충돌 제로, 개발 스트레스 제로!

[3. 팀원 절대 준수 수칙 및 깃허브 협업 가이드 (2가지 방식)]
--------------------------------------------------------------------------------

[수칙 1] ".env" 파일은 절대 깃허브에 올리지 않는다!
  - API 키가 유출되면 즉시 구글 봇에 의해 사용 정지(폭파)됩니다.
  - 키는 각자의 컴퓨터 메모장(.env)에만 저장하고 로컬에서만 사용합니다.

[수칙 2] "내 방(폴더) 밖은 쳐다도 보지 않는다!"
  - 본인 과목 폴더 안에서만 파일을 수정하면 깃허브 충돌(Conflict) 확률은 0%입니다.

[수칙 3] 깃허브 업로드 가이드 (본인 편한 방식 선택)

  방법 A. 터미널(CLI / 아나콘다 파워쉘)을 이용한 족집게 업로드
    - 주의: "git add ." (마침표) 명령어는 절대 사용 금지! (남의 폴더까지 올라감)
    - 명령어 순서:
        1) git add korean/             (본인 과목 폴더만 콕 집어서 추가)
        2) git commit -m "국어 기능 완성"
        3) git pull origin main        (충돌 방지를 위해 푸시 전 최신 내용 가져오기)
        4) git push origin feature/korean

  방법 B. 깃허브 명령어를 잊어버린 분들을 위한 쉬운 업로드 (GUI / 웹)
    - [파이참 GUI 사용 시]:
        1) 파이참 좌측 [Commit] 패널 클릭 (단축키 Alt + 0)
        2) 변경된 파일 목록 중 본인 폴더(예: korean/) 앞의 체크박스만 선택 (다른 폴더 체크 해제)
        3) 커밋 메시지 입력 후 [Commit and Push] 클릭
    - [깃허브 웹사이트 직접 업로드 시]:
        1) 인터넷 브라우저로 팀 깃허브 리포지토리 접속
        2) 상단 우측 [Add file] -> [Upload files] 버튼 클릭
        3) 본인 컴퓨터 바탕화면의 본인 과목 폴더(예: korean/)를 브라우저 창으로 드래그 앤 드롭
        4) 하단 [Commit changes] 버튼 클릭하여 업로드 완료

[추가 가이드 2] 로컬 서버 구동 및 외부 공유 가이드 (Cloudflare Tunnel)
======================================================================
1. 백엔드 웹 서버 구동 방법 (터미널 1):
   - 프레임워크: FastAPI + Uvicorn
   - 실행 명령어:
     uvicorn server:app --port 8000 --reload
   - 옵션 및 동작 원리:
     * '--port 8000': 8000번 포트로 로컬 웹 서버 개설 (내 PC 주소: http://localhost:8000)
     * '--reload': 코드(server.py) 수정 후 저장 시 서버가 자동으로 재시작되어 실시간 반영됨.

2. 팀원 간 실시간 테스트 외부 공유 방법 (터미널 2):
   - 별도의 공유기 포트포워딩 설정 없이 무료 터널링 툴(Cloudflare Tunnel)을 사용.
   - 백엔드 서버(터미널 1)가 실행 중인 상태에서 새 터미널을 열고 아래 명령어 실행:
     cloudflared tunnel --url http://localhost:8000
   - 터미널 화면에 생성된 임시 HTTPS 도메인(예: https://xxx.trycloudflare.com)을 팀원에게 전달하면
     외부 네트워크(모바일, 타 PC)에서도 즉시 내 로컬 서버로 접속 가능.
   
   - 주의사항:
     * 서버터미널(터미널 1)와 터널터미널(터미널 2)이 "둘 다 켜져 있어야" 외부 접속이 유지됨.
     * 터널 터미널 창을 닫으면 임시 링크는 즉시 소멸되며, 다시 명령어를 치면 새 링크가 즉시 재발급됨.
     * 백엔드 코드 수정이나 서버 재시작 시에는 기존 발급된 터널 링크가 끊기지 않고 그대로 유지됨.

3. 웹 배포 구조의 차이점 및 활용 기준 (단일 HTML vs 서버.py + HTML):
   [A] 단일 HTML 방식 (Self-Contained 독립 실행형):
       - 구조: HTML 파일 하나 안에 화면 디자인(CSS)과 통신 로직(JavaScript)을 모두 패키징.
               브라우저 자체 fetch() 기능으로 구글 Gemini API를 직접 호출.
       - 장점: 파이썬 설치나 로컬 서버 구동이 0% 불필요. 파일만 전송하면 더블클릭으로 즉시 실행.
       - 단점: 실행하는 사용자가 자신의 API 키를 브라우저 화면에 직접 입력해야 함 (키 노출 주의).
       - 활용: 파이썬 환경이 없는 비개발자나 지인에게 결과물을 빠르게 단독 배포/체험시킬 때 유용.

   [B] 서버.py + HTML 방식 (Client-Server 표준 아키텍처):
       - 구조: 브라우저(HTML)는 화면 표시 및 단순 호출만 담당하고, 파이썬 서버(server.py)가
               API 통신, 비즈니스 규칙 검증, 프롬프트 제어 등 핵심 두뇌 역할을 전담.
       - 장점: API 키를 서버 내부(.env)에 완벽하게 숨길 수 있어 보안이 철저함.
               DB 연동, 사용자 인증, 복잡한 교육용 AI 에이전트 파이프라인 확장에 필수적.
       - 단점: 파이썬 환경 구축 및 서버 프로세스 구동이 필수적.
       - 활용: EduMate AI 본 프로젝트 및 실무 서비스의 절대적인 기본 표준 아키텍처.

1. 과목별 전담 폴더('app/subjects/[과목]/') 파일 구성 원칙
   조장에게 최종 병합되는 접점은 오직 'router.py' 하나입니다.
   조원들은 필수 파일 3종을 반드시 구비하되, 내부 로직 분리는 자유롭게 진행합니다.

   (1) router.py [필수]
       - 역할: 과목 전용 FastAPI APIRouter 정의 및 단독 구동 지원.
       - 필수 규칙:
         * 메인 병합용 라우터 선언:
           router = APIRouter(prefix="/과목영문명", tags=["과목한글명"])
         * AI 호출 등 실제 기능 구현은 router.py 내부에 직접 다 짜도 되고, 
           본인 재량에 따라 별도 파이썬 파일(예: service.py 등)을 만들어 분리 임포트해도 무방함.
         * 하단에 '단독 테스트 실행 블록'을 반드시 작성하여, Uvicorn 및 파이썬 직접 실행 시
           'app' 객체 부재 에러가 나지 않도록 FastAPI() 인스턴스('app')를 명시할 것.

       - router.py 하단 표준 템플릿:
         if __name__ == "__main__":
             import uvicorn
             from fastapi import FastAPI
             import webbrowser

             # 단독 실행용 FastAPI 인스턴스 (변수명을 반드시 app으로 지정)
             app = FastAPI(title="EduMate AI - [과목명] 단독 테스트 서버")
             app.include_router(router)

             @app.get("/")
             async def root_page():
                 from fastapi.responses import FileResponse
                 from pathlib import Path
                 return FileResponse(str(Path(__file__).resolve().parent / "index.html"))

             PORT = 8000
             webbrowser.open(f"http://localhost:{PORT}")
             uvicorn.run(app, host="0.0.0.0", port=PORT)

   (2) index.html [필수]
       - 역할: 학생이 퀴즈를 풀고 점수/피드백을 확인하는 과목 전용 웹 화면.

   (3) curriculum.txt [필수]
       - 역할: 학년/단원별 핵심 키워드가 정리된 원본 목차 텍스트 데이터.

   (4) quiz_logs.py [선택]
       - 역할: 과목별 상세 풀이 로그 테이블 연동 및 기록을 구현할 조원이 선택적으로 작성.

   (5) ... [자율 확장]
       - 조원 본인의 개발 스타일에 따라 추가 헬퍼 스크립트, 보조 모듈, 프롬프트 파일 등을 
         자유롭게 생성하여 구성 가능 (단, 외부 노출 엔드포인트는 반드시 router.py에 연결할 것).

2. Uvicorn 및 서버 구동 표준 규칙 (수업 방식 통일)
   명령어 인식 및 모듈 로딩 에러를 원천 차단하기 위해 아래 표준 명령어로 구동합니다.

   [규칙 A] 과목 담당 조원 단독 테스트 (본인 과목 폴더 내부에서 구동)
       - 터미널 위치: app/subjects/[과목명]/
       - 표준 실행 명령어 (택1):
         1) python router.py
            (가장 추천: 내장된 uvicorn이 실행되며 브라우저 창까지 자동 오픈)
         2) uvicorn router:app --port 8000 --reload
            (수업 표준 방식: router.py 내의 app 인스턴스를 직접 구동)

   [규칙 B] 팀 통합 메인 관제탑 구동 (조장 및 전체 통합 테스트)
       - 터미널 위치: 프로젝트 루트(edumate_project/)
       - 표준 실행 명령어:
         uvicorn app.main:app --port 8000 --reload
       - 동작: app/main.py가 각 과목의 router를 include_router로 조립하여
         전체 과목 플랫폼을 단일 포트(8000)에서 통합 서비스함.

3. 공유 파일 API 키 연동 표준 규칙 (환경변수 다중 폴백 메커니즘)
   팀원 각자의 로컬 실행 환경(단독 폴더 실행 vs 루트 메인 통합 실행)과 OS 설정 차이로 인한
   키 누락 충돌을 원천 차단하기 위해, API 연동 코드는 반드시 아래 표준 방식을 준수합니다.

   - 필수 로드 순서:
     1) 현재 과목 폴더의 '.env' 확인
     2) 상위 부모 폴더(프로젝트 루트)의 '.env' 순차적 확인 및 로드
     3) 컴퓨터 OS 시스템 환경변수에 등록된 'GEMINI_API_KEY' 최종 폴백 확인
     4) 키가 없을 경우 직관적인 한글 예외 에러 안내 출력

   - 표준 안전 연동 코드 스니펫:
     import os
     from pathlib import Path
     from dotenv import load_dotenv
     from google import genai

     # 1단계: .env 안전 계단식 탐색
     current_dir = Path(__file__).resolve().parent
     parent_dir = current_dir.parent

     if (current_dir / ".env").exists():
         load_dotenv(dotenv_path=current_dir / ".env")
     elif (parent_dir / ".env").exists():
         load_dotenv(dotenv_path=parent_dir / ".env")
     elif (parent_dir.parent / ".env").exists():
         load_dotenv(dotenv_path=parent_dir.parent / ".env")
     else:
         load_dotenv()

     # 2단계: 시스템 환경변수 및 .env에서 키 추출
     api_key = os.getenv("GEMINI_API_KEY")

     # 3단계: 최신 Google GenAI SDK v1 규격 클라이언트 생성
     if not api_key:
         raise ValueError("GEMINI_API_KEY가 설정되지 않았습니다. .env 파일이나 시스템 환경변수를 확인하세요.")

     client = genai.Client(api_key=api_key, http_options={"api_version": "v1"})
